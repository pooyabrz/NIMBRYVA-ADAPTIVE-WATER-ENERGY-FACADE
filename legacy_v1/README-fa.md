# آزمایشگاه محلی نمای تطبیقی آب و انرژی — گام دوم

این بسته برای اجرای روی رایانهٔ شماست. نمایش سه‌بعدی با کد پایتون و پنجرهٔ محلی Matplotlib ساخته شده؛ مرورگر، سرویس ابری و کلید API برای نمایش لازم نیست. دادهٔ آمادهٔ هر ۱۲ شهر در بسته قرار دارد.

**وضعیت علمی:** دادهٔ هواشناسی واقعیِ بازتحلیل‌شده دریافت شده، اما مدل پنل یک مدل مرجع با مرتبهٔ کاهش‌یافته و ضرایب فرضی است. بررسی عددی با اعتبارسنجی عملکرد یک دستگاه فرق دارد. این بسته هنوز شرط «شبیه‌سازی با دقت بالا» را به‌طور کامل برآورده نمی‌کند و هیچ ادعای تولید سالانهٔ معتبر یا برتری RL ندارد. مسیر رسیدن به آن سطح در `docs/HIGH-FIDELITY-PLAN-fa.md` آمده است.

## ۱. شهرها و داده

برای هر شهر، تمام ۸۷۸۴ ساعت سال کبیسهٔ ۲۰۲۴ موجود است: رشت، بندرعباس، یزد، استانبول، سنگاپور، بمبئی، دبی، فینیکس، سویا، لندن، ریکیاویک و لاپاز. این مجموعه ۱۰۵۴۰۸ شهرـساعت دارد. نام اقلیم‌ها توصیف سناریو است؛ طبقه‌بندی رسمی کوپن از روی این یک سال استنتاج نشده است.

دما، رطوبت، نقطهٔ شبنم، فشار سطح، باران، برف، باد، ابر و تابش کوتاه‌موج: ERA5 از Open-Meteo، با انتخاب صریح `models=era5`. تابش بلندموج پایین‌سو: NASA POWER. فایل‌های خام، آدرس دریافت، زمان دریافت و SHA256 در `data/raw/` نگه‌داری شده‌اند. فایل‌های یکسان‌سازی‌شده در `data/normalized/` هستند.

خلاصهٔ عددی سال در `results/city-climate-summary.csv` است. جمع باران این فایل «آب جمع‌شده توسط پنل» نیست. تابش GHI نیز تابش افقی است، نه انرژی الکتریکی پنل. ۲۰۲۴ یک سال تحقق‌یافته است و نمایندهٔ قطعی اقلیم بلندمدت نیست.

## ۲. نصب و اولین اجرا

Python 3.11 یا 3.12 و یک محیط دسکتاپ دارای پشتیبانی GUI برای Matplotlib پیشنهاد می‌شود. فایل ZIP را استخراج کنید و ترمینال را در پوشهٔ `water-facade-lab` باز کنید:

```bash
python -m venv .venv
```

فعال‌سازی در Windows با Command Prompt:

```bat
.venv\Scripts\activate.bat
```

فعال‌سازی در macOS / Linux:

```bash
source .venv/bin/activate
```

سپس:

```bash
python -m pip install -r requirements.txt
python run.py check
python run.py view --city rasht
```

در بعضی سیستم‌ها نام فرمان پایتون `python3` است. در لینوکس، backend گرافیکی و بستهٔ Tk ممکن است جداگانه توسط مدیر بستهٔ سیستم نصب شوند. خطای backend غیرتعاملی یعنی پنجرهٔ دسکتاپ در آن محیط در دسترس نیست؛ برنامه را در Python دسکتاپ خود اجرا کنید.

## ۳. کار با نمایش سه‌بعدی محلی

- با کشیدن ماوس، مدل را بچرخانید.
- فهرست سمت چپ شهر را تغییر می‌دهد؛ نام شهرها در برنامه انگلیسی‌اند تا مشکل فونت و راست‌به‌چپ پیش نیاید.
- `PV surface` یا `Dew surface` سطح رو به محیط را انتخاب می‌کند. باران می‌تواند روی هر دو جمع شود.
- `Tilt` یکی از زاویه‌های ۲۰، ۳۵، ۵۰، ۶۵ و ۸۰ درجه از افق را انتخاب می‌کند.
- `UTC hour` ساعت داده را عوض می‌کند؛ تمام زمان‌ها UTC هستند.
- `Mount` ارتفاع نصب نسبت به زمین را تغییر می‌دهد. ارتفاع جغرافیایی شهر جدا نمایش داده می‌شود.
- `Separate layers` فقط نمایش لایه‌ها را باز می‌کند؛ تغییر جنس، هندسهٔ سازه‌ای و مکانیزم واقعی ساخت را اثبات نمی‌کند.
- دکمهٔ محاسبه، با سطح و زاویهٔ ثابت، حداکثر ۲۴ ساعت را از حالت خشک و دمای هوا گرم‌سازی می‌کند و برآورد ساعت آخر را نشان می‌دهد. این برآورد، خروجی مدل سادهٔ اعتبارسنجی‌نشده است. وجود یخبندان در این بازه، خروجی آب را نامعتبر می‌کند.

مکانیزم مفهومی یک صفحهٔ دوطرفه است؛ تعویض سطح به معنی چرخاندن صفحه برای نمایان‌شدن طرف دیگر است. شیشه‌ای با جنس قابل‌تغییر ساخته یا شبیه‌سازی نشده است. مسیر حرکت، بار باد، آب‌بندی و دوام این سازوکار باید جدا بررسی شود. لوله‌ها و بردارهای تصویر صرفاً مفهومی‌اند و نتیجهٔ CFD نیستند.

## ۴. مدل و کنترل‌های پایه

دو دمای مستقل برای سطح PV و سطح میعان، انتقال گرمای میان آن‌ها، تابش، همرفت، گرمای نهان، باران، تبخیر، ذخیرهٔ فیلم آب و تخلیه محاسبه می‌شوند. وضعیت حرارتی و آب با تعویض سطح صفر نمی‌شود. باتری، بار مصرفی کنترل و انرژی حرکت نیز جدا حساب می‌شوند.

«ابر = میعان بهتر» قانون کنترل نیست: ابر می‌تواند رطوبت را بالا ببرد و هم‌زمان سرمایش تابشی را کاهش دهد. دمای سطح، فشار بخار و موازنهٔ انرژی تعیین‌کننده‌اند. مدل، سردکن فعال ندارد و انرژی خورشیدی را مستقیماً به سرمایش رایگان تبدیل نمی‌کند.

مقایسهٔ اولیه:

```bash
python run.py benchmark
python run.py sensitivity
```

برای هر شهر چهار پنجرهٔ ۹۶ساعته از ۱۵ ژانویه، آوریل، ژوئیه و اکتبر داریم: ۲۴ ساعت آغازین برای گرم‌سازی، ۷۲ ساعت بعدی برای امتیازدهی. کنترل ثابت PV با زاویهٔ ۵۰ درجه با یک کنترل آستانه‌ای علّی مقایسه می‌شود. خروجی‌ها در `results/seasonal/` و فایل خلاصه قرار می‌گیرند. گام زمانی ورودی سقف گام انتگرال‌گیری است؛ در باران شدید و انتقال گرمای تند، برنامه خودکار آن را کوچک‌تر می‌کند.

اگر حتی یک ساعت از پنجره شامل سطح زیر صفر یا برف باشد، نتیجهٔ آب کل آن پنجره نامعتبر می‌شود. برای مقایسهٔ دو کنترل باید اشتراک پنجره‌های معتبر هر دو را استفاده کرد. خروجی‌های تشخیصی پنجره‌های نامعتبر نباید به‌عنوان عملکرد آب یا انرژی تفسیر شوند. این بازه‌ها به سال تعمیم داده نمی‌شوند.

## ۵. محیط یادگیری تقویتی

گزینهٔ اولیه **PPO با فضای عمل گسسته** است. این انتخاب یک نقطهٔ شروع قابل‌اجراست و برتری آن نسبت به MPC یا کنترل ساده اثبات نشده است.

- عمل: انتخاب یکی از ۲ سطح × ۵ زاویه = ۱۰ حالت.
- مشاهده: آخرین شرایط هواشناسی موجود، زمان، بردار خورشید، عرض جغرافیایی، ارتفاع محل، دما و فیلم آب دو طرف، باتری و وضعیت فعلی پنل؛ ۲۷ متغیر.
- پاداش: آب تخلیه‌شده منهای جریمهٔ برق تأمین‌نشده و تعویض زیاد، همراه جریمهٔ کاهش شارژ در پایان دوره. ضرایب با واحد مشخص در `config/model.json` هستند و باید تحلیل حساسیت شوند.
- مرز اطلاعات: عامل در زمان t، دادهٔ موجود تا t را می‌بیند و عمل را برای بازهٔ بعد انتخاب می‌کند؛ هوای تحقق‌یافتهٔ t+1 بعد از انتخاب عمل وارد فیزیک می‌شود. دادهٔ بازتحلیل آینده به‌عنوان «پیش‌بینی» در اختیار عامل قرار نمی‌گیرد.
- فعلاً دوره‌های گرم و بدون برف انتخاب می‌شوند. اگر سطح زیر صفر برود، دوره پایان می‌یابد و نامعتبر علامت می‌خورد. از این آموزش نمی‌توان کارکرد زمستانی یا همهٔ اقلیم‌ها را نتیجه گرفت.

نصب و بررسی محیط:

```bash
python -m pip install -r requirements-rl.txt
python run.py check --rl
```

نمونهٔ آموزش روی سیستم خودتان:

```bash
python run.py train --steps 100000 --seed 7
```

این فرمان روی CPU اجرا می‌شود؛ زمان به سخت‌افزار بستگی دارد. سقف ۱۰۰هزار گام، تضمین همگرایی نیست. برای بررسی تکرارپذیری از چند seed، مثلاً ۷، ۱۹ و ۴۲ استفاده کنید. **در بستهٔ تحویلی سیاست PPO آموزش‌دیده یا امتیاز برتری RL وجود ندارد؛ فقط محیط و کد آموزش آماده‌اند.** کد آموزش با SB3 در این محیط تا پایان اجرا نشده؛ قرارداد محیط با بررسی‌کنندهٔ Gymnasium بررسی شده است.

نمونهٔ دریافت سال مستقل برای ارزیابی؛ به اینترنت نیاز دارد:

```bash
python run.py fetch --years 2025
python run.py prepare --years 2024 2025
python run.py evaluate --policy results/rl/ppo-seed7-2024/policy.zip --year 2025
```

ارزیابی پیش‌فرض، استانبول، لندن، لاپاز و ریکیاویک را که در فهرست پیش‌فرض آموزش نیستند جدا نگه می‌دارد. وضعیت «شهر ندیده» و «سال ندیده» در فایل نتیجه نوشته می‌شود. ارزیابی روی همان سال و شهر آموزش، آزمون تعمیم نیست. در طراحی نهایی، بهترین پارامترها باید با سال اعتبارسنجی انتخاب شوند و سال آزمون تا پایان دست‌نخورده بماند. برای استفاده از پیش‌بینی هوا باید آرشیو پیش‌بینی صادرشده در همان زمان تصمیم را تهیه کرد.

## ۶. ارتفاع و محدودیت مهم

ارتفاع شهر از سطح دریا با فشار محلی در داده وارد مدل می‌شود. ارتفاع نصب پنل، دید آسمان/زمین/دیوار را تغییر می‌دهد. باد ۱۰متریِ بازتحلیل فعلاً بدون اصلاح استفاده می‌شود؛ تغییر ارتفاع نصب، جریان واقعی باد اطراف ساختمان را حل نمی‌کند. «ارتفاع بیشتر = آب بیشتر» از این مدل یا از فشار تنها نتیجه نمی‌شود.

مشخصات ماده، موتور و باتری فرضی‌اند. فیلم آب با تراکم ثابت تقریب زده شده و آب خروجی تصفیه نشده است. مدل فاقد یخ، مه، جریان سه‌بعدی باد، قطرات چنداندازه، ترشوندگی واقعی و تحلیل سازه‌ای است. جزئیات در `docs/METHOD.md` و مسیر ارتقا در `docs/HIGH-FIDELITY-PLAN-fa.md` قرار دارد.

## ۷. ترتیب ادامهٔ پژوهش

۱. اجرای بررسی‌ها و نمایش محلی با بستهٔ حاضر.

۲. تعیین جنس دو سطح، مقطع لایه‌ها، ساختمان مرجع و محدودیت موتور با مشخصات منتشرشده، پیش از تنظیم نهایی پاداش RL.

۳. ساخت موارد مرجع پرجزئیات و اعتبارسنجی اجزای فیزیک با داده‌های آزمایشگاهی منتشرشده؛ آزمایش فیزیکی شخصی لازم نیست، اما بدون مرجع مستقل نمی‌توان ادعای دقت تجربی کرد.

۴. ساخت مدل جانشین از موارد پرجزئیات، سپس آموزش PPO با عدم‌قطعیت پارامترها، و مقایسه با کنترل ثابت، آستانه‌ای و MPC روی شهر/سال مستقل.

۵. گزارش آب، سهم باران و میعان، انرژی مصرفی، انرژی قابل‌استفاده، تعداد حرکت‌ها و بازهٔ عدم‌قطعیت. در نسخهٔ فعلی، سهم منابع ورودی جداست اما منشأ آب مخلوطِ تخلیه‌شده ردیابی نمی‌شود؛ سهم میعان از مخزن نهایی هنوز یک خروجی معتبر نیست.
